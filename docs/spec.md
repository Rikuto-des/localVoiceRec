# 社内向け 会議録音アプリ 仕様書
**バージョン:** 0.1（ドラフト）
**作成日:** 2026-05-27
**ステータス:** レビュー前ドラフト
**分類:** 社内限定 / 機密
---
## 1. 概要
社内会議を Mac 上で録音し、デバイス内で文字起こし・構造化要約まで完結させる macOS ネイティブアプリ。
外部 SaaS（Granola、Otter 等）の利用が社内ポリシーで禁止されているため、**音声・文字起こし・要約のすべてを端末内で処理し、データを一切外部に送信しない**ことを最優先の設計要件とする。会議アプリ（Zoom / Teams / Meet 等）にボットを参加させず、Mac が再生・収音する音声を OS レベルで直接取得する。
---
## 2. 目的と背景
| 項目 | 内容 |
|---|---|
| 解決したい課題 | 会議の議事録作成が手作業で負担。外部ツールは情報持ち出しになるため使用不可。 |
| 既存ツールの問題 | クラウド型は音声・文字起こしが外部サーバーに送信される。会議にボットが参加し相手にも可視。 |
| 本アプリの価値 | 完全オンデバイス処理。外部送信ゼロ。ボット不参加で相手に気づかれず録音可能。 |
| 想定利用者 | 社内従業員（議事録を取りたい会議参加者） |
---
## 3. 対象環境
| 項目 | 要件 |
|---|---|
| OS | macOS 26 (Tahoe) 以降 |
| CPU | Apple Silicon（M1 以降）必須 |
| メモリ | 8GB 以上推奨（オンデバイス推論のため） |
| ネットワーク | **不要**（オフラインで全機能が動作すること） |
| 配布対象 | 社内管理端末のみ |
> Apple Silicon と macOS 26 を要件とするのは、後述の SpeechAnalyzer / Foundation Models が前提とするため。
---
## 4. 設計原則
1. **オンデバイス完結** — 音声・文字起こし・要約は端末外に一切出さない。
2. **ネットワーク遮断** — アプリにネットワーク権限を付与しない。技術的に外部送信を不可能にする。
3. **最小権限** — 必要な OS 権限（マイク・画面収録）のみを要求する。
4. **透明性** — 録音中であることをユーザーが常に把握できる UI。
5. **データ主権** — 録音データの保存・削除をユーザーが完全に制御できる。
---
## 5. 機能要件
### 5.1 録音（2チャンネル取得）
- 自分の声を **マイク入力**、相手の声を **システム音声出力（ループバック）** から、それぞれ独立したチャンネルとして取得する。
- 会議アプリの種類に依存せず動作すること（Zoom / Teams / Google Meet / その他、Mac から音が出る任意のアプリ）。
- 録音の開始・停止・一時停止をメニューバーから操作できること。
- 録音中はメニューバーアイコンで状態を明示すること。
> **設計意図:** マイクとシステム音声を物理的に分離することで、話者分離（ダイアライゼーション）を AI 推定に頼らず「どちらのチャンネルか」だけで確定できる。精度・処理コストの両面で有利。
### 5.2 文字起こし
- デバイス上の **SpeechAnalyzer**（macOS 26 標準）でローカル文字起こしを行う。
- タイムスタンプ付きで出力すること。
- チャンネル情報（自分 / 相手）を保持し、発話者を区別すること。
- 多言語（少なくとも日本語・英語）に対応すること。
- 文字起こし処理中にネットワークを使用しないこと。
### 5.3 要約
- デバイス上の **Foundation Models**（Apple Intelligence のオンデバイスモデル、約 3B）で構造化要約を生成する。
- 出力する構造化項目:
  - 概要
  - 決定事項
  - アクションアイテム（担当・期限が言及されていれば併記）
  - 未解決の問い
  - レビュー項目
- 要約はいつでも再生成できること（元の文字起こしを保持）。
- `@Generable` による構造化出力で、UI に直接マッピングできる形式とする。
### 5.4 データ管理
- 録音・文字起こし・要約は端末内のローカルストレージに保存する。
- 一覧表示・検索・個別削除・一括削除ができること。
- 削除時は実データを確実に消去すること（ゴミ箱経由ではなく即時削除を選択可能に）。
- データ保存場所はアプリのサンドボックス内とする。
### 5.5 UI
- メニューバー常駐型アプリ（`MenuBarExtra`）。
- 録音操作、過去の録音一覧、文字起こし・要約の閲覧を提供。
- 録音中の視覚的インジケータ。

| 区分 | 要件 |

| プライバシー | テレメトリ・解析・クラッシュレポートの外部送信を行わない。 |
| パフォーマンス | 1時間の会議で、録音停止後の要約生成が実用的な時間（数分以内）に収まること。 |
| 可用性 | オフライン環境で全機能が動作すること。 |
| 保守性 | OS 標準フレームワーク中心とし、外部依存を最小化する。 |

## 7. アーキテクチャ
### 7.1 コンポーネント構成
```
┌─────────────────────────────────────────────┐
│              メニューバーUI (SwiftUI)          │
│         録音操作 / 一覧 / 文字起こし・要約表示    │
└───────────────┬─────────────────────────────┘
                │
   ┌────────────┼───────────────┬──────────────┐
   ▼            ▼               ▼              ▼
┌───────┐  ┌──────────┐  ┌────────────┐  ┌──────────┐
│録音    │  │文字起こし  │  │要約         │  │データ層   │
│エンジン│  │エンジン    │  │エンジン      │  │(ローカル)  │
└───┬───┘  └────┬─────┘  └─────┬──────┘  └────┬─────┘
    │           │              │              │
  Core Audio  Speech-        Foundation     サンドボックス
  / SCKit     Analyzer       Models         内ストレージ
 (2ch取得)   (ローカル)      (ローカル3B)
```
### 7.2 データフロー
1. **収音** → マイク（自分）＋システム音声（相手）を 2 チャンネルで取得し、ローカルに音声ファイルとして保存。
2. **文字起こし** → 各チャンネルを SpeechAnalyzer に渡し、タイムスタンプ＋話者区別付きテキストを生成。
3. **要約** → 文字起こしテキストを Foundation Models に渡し、構造化要約を生成。
4. **保存** → 音声 / 文字起こし / 要約をローカルに保存。
> **重要:** このフローのどの段階でもネットワークを経由しない。

## 8. 技術スタック
| レイヤー | 採用技術 | 備考 |
|---|---|---|
| 言語 | Swift | ネイティブ必須（後述の Apple フレームワークが Swift 前提） |
| UI | SwiftUI（`MenuBarExtra`） | メニューバー常駐 |
| マイク収音 | AVAudioEngine | 標準 |
| システム音声収音 | Core Audio process tap（`AudioHardwareCreateProcessTap` / `CATapDescription`）または ScreenCaptureKit 音声ストリーム | **最大の技術的難所**。2ch のサンプルレート・タイムスタンプ同期に注意。 |
| 文字起こし | SpeechAnalyzer | macOS 26 標準・オンデバイス |
| 要約 | Foundation Models | オンデバイス約3B・`@Generable` で構造化出力 |
| 永続化 | SwiftData または Core Data | サンドボックス内ローカル |

## 9. セキュリティ設計（最重要）
社内ポリシー（外部ソフト不可・情報持ち出し禁止）を満たすための中核設計。
### 9.1 ネットワーク遮断
- App Sandbox を有効化し、**ネットワーク関連の entitlement を一切付与しない**。
  - `com.apple.security.network.client` を付けない。
  - `com.apple.security.network.server` を付けない。
- これにより、アプリは技術的に外部通信ができない状態となる。「送らない実装」ではなく「送れない構造」にすることで、監査・説明が容易になる。
### 9.2 権限（TCC）
| 権限 | 用途 | 要求タイミング |
|---|---|---|
| マイク | 自分の声の収音 | 初回録音時 |
| 画面収録 | システム音声の取得 | 初回録音時 |
- 上記以外の権限は要求しない。
### 9.3 データ保護
- データはアプリサンドボックス内に保存し、FileVault（端末暗号化）前提で運用。
- アプリレベルでの保存データ暗号化の要否は社内セキュリティ基準に従う（**要確認**）。
- テレメトリ・解析・自動アップデートの外部通信を実装しない。
### 9.4 配布・署名
- 社内 Apple Developer アカウントで署名・公証（Notarization）。
- 配布方法は MDM 経由のプッシュ配布を想定（**要確認**）。
- 自動アップデート機構を入れる場合も、配布元を社内に限定する。

## 12. 制約・前提
- macOS 26 以降・Apple Silicon 端末に限定される（社内端末がこれを満たすことが前提）。
- オンデバイス約3Bモデルのため、長文・複雑な推論を要する要約では精度に限界がある。短い構造化抽出（決定事項・アクションアイテム）は実用域。
- 会議アプリ側の規約・社内録音ポリシーへの準拠は別途確認が必要。
